03 / WHAT CHANGED IN THE CODE

The differences that stood out.

Observations about these implementations,
not a verdict on every app built with them.

01

The form is a useful contrast

React replaces the edited object with a setter. Vue uses v-model on its reactive draft. Angular uses [value] and (input) with a signal.

This Angular app does not use Angular Forms or ngModel.

02

Save results take different routes

React's save callback returns a boolean to the editor. Vue and Angular emit the movie list upward, then pass a save error back down through a prop or input.

Same user goal; different communication choices.

03

A new year resets the season

React changes key={year} to remount its calendar. Vue watches the year. Angular checks the year in its date-refresh method and resets state explicitly.

react/src/App.tsx:17 · vue/src/App.vue:27 · angular/src/app.ts:47

04

The flip is just CSS

All three toggle an is-open class. The same rotateY(180deg) transition does the animation, with a reduced-motion rule.

Angular adds a small host layout rule because its component element remains in the DOM.

Before comparing: a few important differences

The current preview dates differ. React and Angular simulate December 10. Vue simulates November 30, so its editor is visible. Align the scenario before comparing their screens.

The test settings differ too. Vue and Angular have a 'before-december' mode. React has a December day or the real date, so it lacks that deterministic editing test mode.

Development timing is not an equal test. React enables StrictMode. Angular disables its CLI disk cache and prebundling, and polls for file changes. These configuration choices would affect development measurements.

Storage depends on the origin. All three use the same year-specific keys. Different localhost ports isolate them; hosting them under one origin would make the keys overlap.

How these numbers were measured

Source counts include .ts, .tsx, .vue and application-template .html files under src. They include comments and blank lines; they exclude the entry index.html, CSS, configuration, dependencies and generated output. Component lines exclude the entry point, date helpers, movie data and storage helpers.

Dependency counts are the entries in dependencies and devDependencies in each package.json, not transitive packages. Angular's count includes framework packages and RxJS; the application source does not use RxJS.

Formatting affects line counts: several templates are compressed onto single lines. Framework scope, available functionality, tooling and team practices also need context. There are no build-time or bundle-size rankings here because this report has not established a controlled benchmark.

Versions come from package-lock.json. Snippets and measurements are a saved source snapshot, not live connections to the applications.

06 / CHOOSING FOR A PROJECT

Start with the work.
Then choose the tools.

This experiment compares one small app, not everything each framework can do. It does not establish an objective winner.

What does the project need?

Consider routing, forms, data loading, accessibility and testing. These calendars use no router or backend, and do not test the frameworks' full capabilities.

What does the team already understand?

Experience with JSX, Vue templates or Angular classes can affect learning time. Familiarity and clear conventions matter more than a line-count ranking.

How much structure is useful?

Compare React's functions and hooks, Vue's script/template structure, and Angular's component metadata and typed inputs. Choose conventions the team can explain and maintain.

What will maintenance require?

Evaluate tooling, testing, upgrades, documentation and ecosystem packages for the real project. This small experiment does not measure ecosystem quality or long-term maintenance costs.
